# Injection Moulding — 100 original candidates

Roster from a one-off manual audit of 100 ChatGPT-sourced injection-moulding
candidate suppliers, run 2026-08-17/18. Reference data, not generated by
this codebase — checked in so `main.py status --category "injection
moulding"` has a durable place to read the dead/rejected/mismatch buckets
from (they have no representation in the database: these candidates were
bulk-imported outside the normal `discover()` pipeline, so `suppliers.
product_keywords`/`primary_categories` are blank on every one of them, and
"genuinely dead"/"other rejected"/"name mismatch" were never DB concepts to
begin with — a rejected candidate that failed validation never became a
supplier row at all).

Only changes if the audit is deliberately re-run by hand — nothing in this
codebase writes to these files automatically.

- `confirmed.csv` (42) — candidates that resolved to a real, validated
  supplier. Company Name/Website only; `main.py status --category` re-checks
  each against the live DB (still exists, still unflagged) rather than
  trusting this file's snapshot blindly.
- `excluded.csv` (15) — candidates confirmed at some point but later
  excluded (not a direct manufacturer: broker/network model, wrong category,
  or failed re-validation). Re-checked against `suppliers.flagged` live,
  same reasoning as confirmed.csv.
- `genuinely_dead.csv` (19) — no live website found at all, and no
  validated alternate domain either. Static; no live DB signal applies (see
  README intro).
- `name_mismatch.csv` (3) — a real site was fetched, but the extracted
  company name didn't match the originally supplied name closely enough.
  Static.
- `other_rejected.csv` (21) — real site fetched, name matched, but some
  other validation gate failed (usually: fetched page never mentions the
  product term, or no company name found in page text at all). Static.

Three names (OzMetal Plastik, Wirth Werkzeugbau, Formplast) were removed
from the original `genuinely_dead.csv` snapshot before checking in — an
alternate domain was found and validated for each during the same audit
session, moving them into `confirmed.csv` instead. This file reflects that
correction already; no separate exclusion list is needed downstream.
